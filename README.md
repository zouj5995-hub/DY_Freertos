# DY 电源板 LoRa 上位机

这是一个零依赖、单 HTML 文件的现场调试台，使用浏览器 Web Serial API 通过 USB 转串口 + LoRa 透传模块维护 DY 电源板。

手机 OTG / CH340 原生 Android APK 工程见：[android/README.md](android/README.md)。

## 先解决安全上下文

Web Serial **不能直接用 `file://` 双击打开**。现场建议：

1. 确认电脑安装了 Python 3，并将 USB 转串口接好。
2. 双击仓库根目录的 `start-dy-lora-console.bat`。
3. 浏览器打开 `http://localhost:8000/dy-lora-console.html` 后，再点击“连接串口”。

也可以在仓库根目录运行：

```bat
python -m http.server 8000
```

然后用 Chrome / Edge 89+ 打开上面的地址。串口授权必须由“连接串口”按钮的用户点击触发。

## 使用顺序

1. 点击“连接串口”，在浏览器弹窗中选择 LoRa USB 串口。参数固定为 **9600 / 8N1，无校验，无流控**。
2. 确认船号（默认 `01`）。点击“读设备状态”查看时间、电压、三路温度和 8 台设备状态。
3. “读控制策略”会回读完整 35 条规则。表格按使用习惯填写“开始时间 + 结束时间”，页面会自动计算并显示协议层的持续秒数；下发前确认二次弹窗后整表覆盖设备。
4. 校时面板里的“使用电脑时间”取本机北京时间，发送时自动转换为 UTC（北京时间减 8 小时）。校时无 ACK，发送后重新读取状态确认。
5. “重启板子”是不可逆操作，必须在二次确认后发送。
6. 通信日志保留最近 1000 条，包含时间、方向、原始 HEX 和解析摘要，可导出为 TXT。

## 协议实现要点

- `$READ`、`$GETSTR`、`$STR`、`$REST` 使用协议头 + 船号 + 数据 + Modbus CRC16（大端）+ `$OVER`。
- 接收缓冲按 `$ACK` 14 字节、`$STAR` 30 字节、`$STR` 222 字节切帧，支持 `$ACK` + `$STAR` 连续到达。
- 年份、电压、温度、规则时长按小端解析；温度按有符号 16 位处理。
- `$BDRMC` 是唯一的纯文本指令，不带船号、CRC 或 `$OVER`，且设计上无应答。
- 策略表的结束时间仅是上位机编辑层；发送 `$STR` 时仍按协议写入 16 位小端持续秒数。结束时间早于开始时间按跨午夜处理；活动规则超过 65535 秒会阻止发送。
- 发送帧严格使用协议规定的 CRC 大端；接收侧额外兼容当前固件 `packed uint16_t` 在小端 MCU 上产生的 CRC 小端回包，日志会标注“兼容固件 CRC 小端”。

## 离线检查界面

打开 `http://localhost:8000/dy-lora-console.html?demo=1` 可加载本地演示状态和策略数据。演示模式不会访问串口，真实操作仍需正常连接。

## 常见问题

- **看不到串口授权弹窗**：确认是 Chrome / Edge，且点击的是页面里的“连接串口”；不要从 `file://` 打开。
- **收到 CRC 错误**：检查 LoRa 两端串口参数是否均为 9600 / 8N1，并导出日志反馈原始 HEX。
- **校时差 8 小时**：不要自行把时间改成 UTC；页面会从本机时间自动换算，发送日志中会显示 `$BDRMC,...` 文本。
- **浏览器关闭后端口被占用**：返回页面点击“断开”，或重新插拔 USB 转串口。
